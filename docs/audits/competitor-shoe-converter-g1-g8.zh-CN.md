# 竞品鞋码转换器体验审计与差异化方案

审计日期：2026-07-26
证据：`docs/imgs/g1.jpg` 至 `g8.jpg`
范围：鞋码对照表、男/女/童切换、输入体系选择、换算结果、广告和基础无障碍风险。

## 总体判断

这款竞品做到了“打开就能查”，但产品仍停留在静态对照表和数字滚轮层面。它展示了很多数字，却没有回答购买决策真正关心的问题：

- 这是标准近似值还是品牌官方值？
- `cm` 是实测脚长还是鞋盒标签？
- 某个品牌或鞋款偏大、偏小吗？
- 儿童 C/Y 编号跨阶段时有没有重置？
- 脚宽、左右脚差异和相邻码怎么选？
- 为什么推荐这个码，结果来自哪里？

我们的差异化不应是“做一个更漂亮的表格”，而应是“从查表工具升级为可解释的购买决策助手”。

## 流程步骤

### 1. 男款对照表——基础可用，决策能力弱

![竞品男款对照表上半部分](../../imgs/g1.jpg)

![竞品男款对照表下半部分](../../imgs/g2.jpg)

健康度：一般。

优点：

- 男、女、童入口明显。
- 六列主要体系集中展示。
- 数字字号较大，深色模式下主体清晰。

问题：

- 表头滚出屏幕后，用户只能凭记忆判断每一列是什么。
- 只有 US、UK、EU、cm、KR、in；中国、Mondopoint 和 JP 只通过一句注释模糊处理。
- 没有说明数据来源、版本、标准、市场或品牌。
- 用户需要长距离滚动寻找尺码。
- 没有高亮用户正在比较的行，也没有相邻码差异。

### 2. 女款对照表——切换清楚，但仍是同一张“万能表”

![竞品女款对照表上半部分](../../imgs/g3.jpg)

![竞品女款对照表下半部分](../../imgs/g4.jpg)

健康度：一般偏弱。

优点：

- 受众切换状态醒目。
- 男女 US 差异直接体现在表格中。

问题：

- 整个女鞋市场被压缩成一套固定关系，没有品牌、鞋型或市场上下文。
- 没有区分技术标准与品牌实际标注。
- `JP 与 cm 使用同一标准（脚长）` 容易让用户把品牌的 CM/JP 标签误认为实测脚长。
- 滚动后仍丢失列标题。

### 3. 童款对照表——覆盖 C/Y 是优点，解释不足是高风险

![竞品童款 C 段](../../imgs/g5.jpg)

![竞品童款 C/Y 重置段](../../imgs/g6.jpg)

健康度：风险较高。

优点：

- 保留了 C 和 Y 标签。
- 页面实际展示了 13C 到 1Y、1.5Y 到 2Y 的编号转换。

问题：

- 没有解释 C/Y 阶段和 UK 编号重置。用户只看到 UK 从 13 变为 1，很容易怀疑数据错误。
- 页面将 `cm` 与 `KR` 都描述为脚长，但部分行并非精确十倍关系。例如 8.5C 显示 `15.3 cm` 与 `155 KR`。这可能来自不同标签或不同舍入源，但 UI 没有解释。
- 童鞋没有婴童、小童、大童的分段标题。
- 没有测量方式、成长余量或“不要人为加一码”的说明。
- 来源不明，无法判断该表是通用标准还是某个品牌表。

结论：这些数据可以作为竞品行为证据，不能直接导入我们的生产数据。

### 4. 体系选择——操作直接，但术语不够友好

![竞品输入体系选择](../../imgs/g7.jpg)

健康度：基本可用。

优点：

- 一次选择输入体系。
- 下拉项触控区域较大。
- 当前选择有勾选反馈。

问题：

- 只有缩写，没有“美国童鞋 / 英国 / 欧码 / 实测脚长”等解释。
- 弹层遮挡结果，缺少搜索和最近使用。
- JP、cm、KR 同时出现，但没有解释“标签”与“测量”的区别。
- 顶部表格、交换、设置图标没有文字标签，含义依赖猜测。

### 5. 换算结果——速度快，但不能支撑购买决定

![竞品换算结果](../../imgs/g8.jpg)

健康度：功能可用，信任较弱。

优点：

- 当前输入 `3Y` 非常醒目。
- 目标尺码按卡片排列，扫读速度快。
- 一屏能看到主要结果。

问题：

- 只有一个结果，没有“建议先试”和相邻备选。
- 没有品牌、产品系列、鞋宽或楦型信息。
- 没有可信度和来源。
- “换算结果为近似值”过于笼统，用户不知道为什么近似。
- 结果不解释儿童阶段，也不防止把 `3Y` 当作 `3C`。
- “More apps by deve”存在截断和中英文混排。
- 大型底部广告持续占据核心任务空间，容易造成误触，也削弱专业可信度。

## 可见的无障碍风险

仅凭截图不能确认完整无障碍合规，但可以看到以下风险：

- 未选中的男/女/童文字对比度偏低。
- 多个图标没有可见标签；需验证 VoiceOver/TalkBack 名称。
- 表格滚动后表头消失，认知负担高，屏幕阅读器也需要明确行列语义。
- 结果只靠红色强调当前值，不能以颜色作为唯一状态。
- 广告与产品内容层级接近，可能干扰焦点顺序和触控。
- 表格需要验证动态字体放大后是否仍能显示六列。

无法从截图确认：

- 键盘和辅助技术焦点顺序。
- 动态字体、横屏、缩放和小屏重排。
- 错误输入、空状态和离线状态。
- 数据是否真正离线、是否有隐私追踪。

## 我们的差异化定位

### 一句话

竞品回答“这些数字大概怎么对应”；我们的产品回答“基于你的测量、购买品牌和具体场景，建议先试什么，为什么，以及哪里可能不准”。

## 差异化矩阵

| 竞品当前方式 | 我们的方式 | 用户价值 |
|---|---|---|
| 一张无来源万能表 | 标准基准 + 品牌 + 市场 + 产品系列 | 知道结果适用于哪里 |
| 只显示目标数字 | 主推荐 + 邻近备选 + 偏紧/偏松影响 | 能直接做购买决定 |
| cm/JP/KR 混在同一层 | 实测脚长、品牌标签、毫米标注分离 | 避免把标签当测量 |
| 男/女/童三档 | 成人男、成人女、婴童、小童、大童 | 防止儿童编号重置误用 |
| 没有品牌 | 官方品牌表和款型覆盖 | 更接近真实商品 |
| 没有宽度 | 脚宽、品牌宽度和楦型提示 | 减少只看长度买错 |
| 没有解释 | 可信度、来源、更新时间、推荐原因 | 建立信任 |
| 每次重新输入 | 多人本地档案和常穿反馈 | 家庭海淘更快 |
| 只有鞋码 | 鞋码 + 上衣 + 下装 + 儿童服装 | 覆盖完整海淘场景 |
| 核心页大型广告 | 核心决策流程不放遮挡式广告 | 更专业、少误触 |

## 我们的首页不应先展示大表

首屏建议先问：

> 你现在知道什么？

三个入口：

1. 我量了脚长。
2. 我知道当前尺码。
3. 使用已保存的档案。

然后渐进询问：

- 给谁购买？
- 哪个品牌、哪个市场？
- 是否知道产品系列？
- 是否需要脚宽建议？

对照表保留为辅助工具，不作为默认主页。

## 推荐结果应怎样呈现

结果首屏：

```text
建议先试：EU 42
Nike 官方尺码 · 高可信

你的右脚 26.4 cm，落在该品牌 EU 42 的官方范围内。
左脚比右脚短 3 mm，按较长脚推荐。

备选 EU 41.5：更贴脚，脚背高时不建议
备选 EU 42.5：空间更大
```

随后提供：

- US/UK/JP/CN/KR/Mondopoint 结果。
- `鞋盒 CM 标签 ≠ 实测脚长` 提示。
- 宽度和产品系列说明。
- 官方来源、抓取日期和数据版本。
- 保存到个人档案。
- “实际穿着：合适/偏大/偏小”的本地反馈。

## 对照表的正确做法

用户主动打开对照表时：

- 固定表头。
- 固定当前选中行。
- 可以输入任一尺码直接定位。
- 默认只显示用户关心的 3–4 个体系，其余可自定义。
- 每列写全称和单位。
- 品牌表与标准表使用不同徽标。
- 儿童编号重置处插入分段标题和说明。
- 所有行可打开“为什么这样对应”的来源详情。

## 广告策略

不要复制竞品在核心结果页底部放大型横幅的方式。

建议：

- 换算输入和结果首屏无广告遮挡。
- 免费版广告只能出现在历史列表末尾或“更多”页面。
- 激励广告用于非必要便利能力，例如增加更多档案，不得影响数据准确性。
- 一次性买断去广告。

专业尺码工具的信任价值高于单次广告展示。

## 不能照搬竞品数据

这 8 张图没有提供来源、版本、市场和授权信息。它们只适合：

- 观察竞品覆盖了哪些字段。
- 发现交互问题。
- 建立我们要验证的测试样例。

它们不适合：

- 直接写入生产尺码表。
- 作为品牌官方数据。
- 覆盖已经取得的 ISO、GB/T 或品牌官方表。

如果要做差异测试，可以把截图行保存为 `competitor_observation`，设置 `productionUse: false`，由自动脚本与我们的权威数据比较，但永远不参与用户换算。
